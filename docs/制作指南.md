# 双轮自平衡机器人 · 零经验制作指南

> **这份指南的承诺**：你不需要会单片机、不需要会控制理论、甚至不需要焊过电路——只要会拧螺丝、会装软件、愿意花大约一周的零碎时间，就能做出一台用 LQR 最优控制 + 卡尔曼滤波平衡、还能跑强化学习策略的双轮自平衡车。
> 每一步都写了"做什么→预期看到什么→不对怎么办"。跟着做，卡住直接跳到第 8 章故障排查按症状查。
>
> 理论推导（为什么这样做）全部在 `docs/双轮自平衡机器人-毕业设计完整方案与答辩手册.docx`，本指南只管"怎么做"。

## 第 1 章 软件安装（全部免费）

### 1.1 STM32CubeIDE（写代码 + 烧录，一站式）

1. 打开 `https://www.st.com/en/development-tools/stm32cubeide.html`，点 **Get Software**，需要注册一个 ST 账号（邮箱验证即可，免费）。
2. 下载 Windows 版安装包（约 1GB，慢慢等）。
3. 双击安装，一路 Next；安装目录**不要带中文和空格**（默认 `C:\ST\STM32CubeIDE_x.x.x` 就很好）。
4. 首次启动会让你选 workspace 目录，同样**不要中文**。
5. 启动后如果弹窗问 **Register/Sign in**，可以跳过（Skip）。

> 卡住点：如果 ST 官网下载太慢，用镜像站搜 "STM32CubeIDE 国内镜像"（如 stmcu.com.cn），但**务必核对版本 ≥ 1.12**。

### 1.2 驱动安装

1. **ST-Link 驱动**：把 ST-Link 插上 USB；打开 CubeIDE 菜单 `Help → ST-LINK Upgrade`，如果它能识别到你的 ST-Link，说明驱动 OK；识别不到就去 ST 官网搜 `STSW-LINK009` 下载驱动包安装。
2. **CH340 驱动**：插上 USB-TTL 模块；打开"设备管理器"（Win+X → 设备管理器），看"端口(COM 和 LPT)"里有没有出现 `USB-SERIAL CH340 (COMx)`。没有就搜 `CH340 驱动` 装一个，装完重新插拔。
3. **验收**：设备管理器里应同时看到 `ST-Link Debug` 类设备和 `CH340 (COMx)`。记下 COM 号，比如 `COM5`。

### 1.3 Python 环境（上位机 + 强化学习用）

1. 装 Python 3.10+：官网或微软商店均可。安装时**勾选 "Add Python to PATH"**。
2. 打开命令提示符（Win+R 输 `cmd` 回车），执行：

```bash
pip install pyserial numpy PyQt5 pyqtgraph matplotlib torch -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> torch 比较大（几百 MB），只需要做强化学习扩展时装；不做可先去掉 `torch`。

### 1.4 （可选）Octave——改机械参数后重算 K

LQR 增益 K 是按机械参数算的。**照抄本仓库参数做，K 不用重算**；只有你改了车重/重心/轮径才需要重算：装 Octave（免费，搜索 "Octave download"），把 `code/design/design_lqr.m` 改参数运行，把输出的 K 抄进 `balance_config.h`。

## 第 2 章 硬件组装与接线

### 2.1 先认识你要接的东西

每个模块的引脚丝印（印在板子上的小字）就是它的名字，接线表里写的名字=丝印名字。

### 2.2 机械组装（按顺序做）

1. **下层板**装两个驱动轮电机（电机支架朝外），电池用扎带/双面胶固定在下层板中央（电池最重，放低放中间，车的重心稳）；
2. 上层板用铜柱架高约 8~10cm（**重心高一点反而好控制**，原因见手册 2.1 节），主控板、TB6612、降压模块放上层的四角；
3. MPU6050 用双面胶贴在**上层板的正中间、水平放置**（箭头/X 轴丝印指向车头方向！这决定后面符号对不对）；
4. 车头方向自定，但之后**不许再改**（改了等于重新标定）；
5. 万向轮装车尾（调试期防侧翻，车能站了拆掉）；
6. 轮子装上电机轴，拧紧轴套螺丝。

### 2.3 电气接线（核心！逐条对照，接完拍照留存）

**接线前铁律**：① 全程断电接线；② 所有 GND 必须连在一起（共地！没共地是一半诡异问题的根源）；③ 接完先检查再上电。

**表 2-1 主控 ↔ MPU6050（I2C）**

| MPU6050 引脚 | 主控引脚 | 说明 |
|---|---|---|
| VCC | 3.3V | — |
| GND | GND | — |
| SCL | **PB8** | I2C1 时钟 |
| SDA | **PB9** | I2C1 数据 |
| XDA / XCL / AD0 | 悬空 | AD0 悬空=地址 0x68，与代码一致 |

**表 2-2 主控 ↔ TB6612（驱动）**

| TB6612 引脚 | 接到 | 说明 |
|---|---|---|
| VM | 电池正极（经 5A 保险丝） | 电机功率电 |
| GND（功率侧） | 电池负极 | — |
| VCC | 3.3V | 逻辑电 |
| STBY | 3.3V | 拉高使能 |
| PWMA | **PA8** | 右电机 PWM（TIM1_CH1） |
| AIN1 | **PB12** | 右电机方向 1 |
| AIN2 | **PB13** | 右电机方向 2 |
| PWMB | **PE11** | 左电机 PWM（TIM1_CH2） |
| BIN1 | **PB14** | 左电机方向 1 |
| BIN2 | **PB15** | 左电机方向 2 |
| AO1 / AO2 | 右电机两根线 | 不分极性，转反了改代码符号 |
| BO1 / BO2 | 左电机两根线 | 同上 |
| GND（逻辑侧） | 共地 | 与主控 GND 相连 |

**表 2-3 编码器（两根电机尾部伸出的细线×2）**

| 电机 | 编码器引脚 | 主控引脚 |
|---|---|---|
| 右电机 | C1(A相) | **PA6**（TIM3_CH1） |
| 右电机 | C2(B相) | **PA7**（TIM3_CH2） |
| 右电机 | VCC / GND | 3.3V / GND |
| 左电机 | C1(A相) | **PB6**（TIM4_CH1） |
| 左电机 | C2(B相) | **PB7**（TIM4_CH2） |
| 左电机 | VCC / GND | 3.3V / GND |

> 编码器 A/B 接反不影响测速大小，只影响速度符号——第 4.4 节符号自检会发现。

**表 2-4 电源**

| 从 | 到 | 说明 |
|---|---|---|
| 电池 + （经保险丝） | TB6612 VM | 电机主功率 |
| 电池 + | 降压模块 IN+ | — |
| 电池 − | 降压模块 IN− / TB6612 GND | 共地 |
| 降压模块 OUT+（**先用万用表调好 5.0V 再接！**） | 主控板 **5V 引脚** | 给主控供电 |
| 降压模块 OUT− | 主控 GND | 共地 |
| 电池 + → 10kΩ → 采样点 | **PA0**（ADC1_IN0） | 电池电压检测 |
| 采样点 → 1kΩ → GND | — | 分压 1/11，代码里乘回 11 |

> ⚠️ 降压模块第一次通电时**不要接主控**，先空载用万用表把输出调到 5.0V（旋钮很灵敏），调好再接。

**表 2-5 调试线（烧录 + 串口）**

| 用途 | 连接 |
|---|---|
| ST-Link | SWDIO→PA13/SWCLK 排针（核心板已引出，接 SWDIO/SWCLK），3.3V、GND |
| USB-TTL | 模块 RX←主控 **PA9**(USART1_TX)；模块 TX→主控 **PA10**(USART1_RX)；GND 共地 |

### 2.4 上电前 6 项检查（万用表逐项过）

1. 电池接口极性：红正黑负，别反（反接=冒烟）；
2. 降压输出：空载 5.0V±0.2；
3. 电源对地短路：万用表蜂鸣档，VM↔GND 不响、5V↔GND 不响；
4. PB8/PB9 上拉：MPU 模块自带 4.7k 上拉，无需另加；
5. 所有 GND 是否全部互通（蜂鸣档逐对测）；
6. 电机线没有和杜邦线松搭（运行中脱落=车暴冲）。

## 第 3 章 建 CubeIDE 工程（逐击配置）

### 3.1 新建工程

1. `File → New → STM32 Project`；
2. 左上搜索框输入 **STM32F407VET**，选 `STM32F407VETx`，Next；
3. 工程名填 `balance_bot`（不要中文），Targeted Language 选 **C**，Binary Type 选 Executable，Finish；
4. 首次弹窗 `Initialize all peripherals with their default Mode?` 点 **Yes**。

### 3.2 时钟树（照抄数字）

左侧 `System Core → RCC`：HSE 选 **Crystal/Ceramic Resonator**。
顶部打开 `Clock Configuration` 标签页：

- `Input frequency` 填 **8**（核心板晶振 8MHz）；
- PLL Source Mux 选 **HSE**；
- `/M` 填 **8**，`×N` 填 **336**，`/P` 填 **2** → HCLK 自动变 **168**；
- 弹窗问是否自动解决时钟问题点 OK；确认：APB1=42、APB2=84、HCLK=168。

### 3.3 外设逐个配（每个字段都列出，照抄）

**I2C1**（`Connectivity → I2C1`）：Mode 选 **I2C**；Parameter → Clock speed = **400000**（Fast Mode）；其余默认。引脚自动落 PB8/PB9。

**TIM1**（`Timers → TIM1`）：Clock Source = **Internal Clock**；Channel1 = **PWM Generation CH1**；Channel2 = **PWM Generation CH2**。
→ 引脚：CH1 自动 PA8；**CH2 默认 PA9，手动改成 PE11**（在芯片图上点 PA9 引脚下拉换 PE11——因为 PA9 要留给串口）。
→ Parameter：Prescaler = **0**，Counter Period = **4199**，auto-reload preload 勾上；CH1/CH2 的 Pulse = 0，Mode = PWM mode 1。

**TIM3**（右电机编码器）：Combined Channels = **Encoder Mode**。引脚 PA6/PA7。Counter Period = **65535**。Encoder Mode = **Encoder Mode TI1 and TI2**（4 倍频）。
**TIM4**（左电机编码器）：同样配置，引脚 PB6/PB7。

**TIM6**（5ms 心跳）：Activated 勾上；Prescaler = **83**（84MHz/84=1MHz），Counter Period = **4999**（1MHz/5000=200Hz）；下方 **NVIC** 栏勾上 `TIM6 global interrupt`，Priority 填 **0**（最高）。

**USART1**：Mode = **Asynchronous**；Baud = **921600**，8-N-1；DMA Settings → Add → USART1_RX：**Circular**（循环），USART1_TX：**Normal**；NVIC 栏 `USART1 global interrupt` 勾上，Priority **6**。

**ADC1**：IN0 勾上（PA0）；采样时间随意（代码里软件触发）。

**IWDG**（独立看门狗）：Activated 勾上；Prescaler = **32**，Counter = **625**（≈500ms）。

**SYS**：Debug 选 **Serial Wire**（不选将无法烧录！）。

### 3.4 生成代码 + 放入本仓库文件

1. `Ctrl+S` 保存 → 弹窗选 **Yes** 生成代码；
2. 把本仓库 `code/stm32/` 下**所有 .c/.h 文件**复制：
   - 所有 `.c` → 工程的 `Core/Src/`（覆盖同名的 main.c 时选替换）；
   - 所有 `.h` → 工程的 `Core/Inc/`；
3. CubeIDE 左侧工程树右键 `Refresh (F5)`，然后 `Project → Build Project`；
4. **编译应 0 Error**（Warning 可忽略）。报错？→ 第 8.2 节。

## 第 4 章 第一次烧录与传感器验证

### 4.1 编译与烧录

1. 工程右键 `Properties → C/C++ Build → Settings → Optimization`：Optimization Level 选 **-O2**；
2. 点工具栏锤子图标编译 → Console 应显示 `Build Finished. 0 errors`；
3. 插上 ST-Link，点绿色虫子图标（Debug）→ 第一次会弹配置确认，直接 OK → 自动烧录并停在 main 开头；
4. 点**播放键**（Resume）让程序跑起来。之后日常烧录用 `Run → Run` 即可。

### 4.2 第一次看数据（最重要的一步）

1. 插 USB-TTL，打开上位机：`python code/host/gui.py COM5`（COM 号换成你的）；
2. 你应看到四条实时曲线。**此时车还躺着没关系**，先做符号自检。

### 4.3 符号自检仪式（三个动作，全对才继续）

| 动作 | 看哪条曲线 | 必须出现的现象 |
|---|---|---|
| 手扶车头**向前倾** | theta（蓝） | 变**正** |
| 把车**向前推** | v（绿） | 变**正** |
| （临时在 main 里手写 `Motor_SetTorque(0.3f);` 烧一次） | — | 两轮都**向前**转 |

任何一个不对：theta 反了→改 `attitude.c` 里 `atan2f(-ax_g, az_g)` 的负号；v 反了→对调该电机编码器 A/B 两根线；电机反了→对调该电机的两根电源线。**三个全对后，把临时代码删掉，重新烧录。**

### 4.4 静止漂移检查

车静止躺平 1 分钟，theta 曲线漂移应 **<0.1°/min**。漂移大 = 上电标零偏时车动了（程序设计要求上电静止）→ 重新上电，等 2 秒再动。

## 第 5 章 标定与起飞

按顺序执行，**一步没达标不要进下一步**。

### 5.1 死区标定（5 分钟）

临时在 main 的 while 循环里加：`Motor_SetTorque(0.05f);` 烧录，逐步改大 0.05→0.08→…直到轮子刚开始转，记录这个力矩对应的占空比。换算：占空比 = 力矩/TORQUE_FULL。实测值填进 `balance_config.h` 的 `DEADZONE`（默认 0.06）。改完删临时代码重烧。

### 5.2 第一次闭环（扶着）

1. 双手扶车保持竖直，等 gating 生效（程序要求静止+竖直 200ms，电机会有轻微自锁感=已进入闭环）；
2. 慢慢松手，车应该能歪歪扭扭站 2~10 秒然后倒下——**这就是成功的第一步**；
3. 车倒下后：轮子立刻停转、不会暴冲 = 故障安全正常。

### 5.3 机械中值标定（关键，车跑偏的根源）

现象：车总朝一边匀加速跑。原因：车体重心没在轮轴正上方（安装误差 0.5° 就会造成恒定加速度）。做法：在 `balance_config.h` 加一个中值补偿——把 `Att_GetTheta()` 的返回值减去中值角 `THETA_MECH`（在 attitude.c 的返回处 `return s_theta - THETA_MECH;`）。多次尝试：车朝右跑 → THETA_MECH 加一点；朝左 → 减一点。**判据：平地上车长时间平均速度≈0。**

### 5.4 直立环整定

只动两个数：`balance_config.h` 里 LQR 权重（重新跑 `design_lqr.m`）或临时微调 K_THETA。

| 症状 | 动作 |
|---|---|
| 高频抖、电机嗡嗡叫 | Q₁(50) 调小一半重算 K |
| 软绵绵、一推就倒 | Q₁(50) 调大一倍重算 K |
| 低频大幅慢摆（喝醉了晃） | 卡尔曼 `KF_R_MEAS` 调大 3→0.1 |

### 5.5 速度环整定

车能站了但会慢慢漂走 → 速度环在干活但参数没调好：`VEL_KP` 从 0.5 起步往上加到"推车有明显回拉感"；`VEL_KI` 加到 3° 缓坡能稳住。加 I 后出现几十秒一次的"呼吸"摆动 = I 过强，减半。

### 5.6 达标判据

静止 60s 波动 ≤±1.0°；侧推到 10° 摆角 2s 内恢复。达标就进第 6 章正式测试。

## 第 7 章 强化学习扩展（可选加分项）

完整流程在 `code/rl/README.md`，三句话版本：

1. `python code/rl/train_ppo.py` —— 在与实车同构的仿真环境里训一个 PPO 平衡策略（CPU 半小时内）；

## 第 8 章 故障排查（按症状查）

### 8.1 软件/电脑侧

| 症状 | 原因 → 解法 |
|---|---|
| CubeIDE 装不上/打不开 | 安装路径含中文/空格 → 卸了重装到纯英文路径 |
| 编译报 `undefined reference to MPU_Init` 等 | .c 文件没复制进 Core/Src 或没 Refresh → 重新复制+F5 |
| 编译报找不到 `balance_config.h` | .h 没进 Core/Inc → 补拷 |
| Debug 连不上 ST-Link | SYS 里没选 Serial Wire；或驱动没装 → 见 1.2/3.3 |
| 设备管理器没有 COM 号 | CH340 驱动 → 重装驱动重插 |
| 上位机 `could not open port` | COM 号写错，或被串口助手占用 → 关掉占用程序 |

### 8.2 车侧（运行期）

| 症状 | 最可能原因 → 解法 |
|---|---|
| 上电立刻朝一个方向猛冲 | θ 或 θ̇ 符号反=正反馈 → 重做 4.3 符号自检 |
| 上电电机狂转不止 | I2C 读失败进故障安全？不是——查 MPU 接线（SCL/SDA 反了时 MPU_Init 应已停机）；狂转说明闭环在跑但姿态错 → 检查 MPU 安装轴向 |
| 车总朝一边匀加速跑 | 机械中值偏 → 5.3 标定 |
| 站 2 秒后越来越抖 | 死区没标或直立环太硬 → 5.1/5.4 |
| 站住了但慢慢漂走 | 正常，速度环没调好 → 5.5 |
| 跑几分钟数据断流 | I2C 死锁 → 固件已带 9 脉冲恢复；仍频繁则 I2C 线远离电机线、缩短 |
| 满电正常越跑越软 | 电压归一化没生效 → 查 PA0 分压电阻 10k/1k |
| 一切正常但换地毯就翻 | 摩擦特性变了 → 重新标死区+中值（5.1/5.3） |

### 8.3 一条万能归因顺序

**先查符号（4.3）→ 再查数据（遥测曲线是否合理）→ 再查参数（K/KF/PI 是否被改乱）→ 最后才怀疑代码**。本仓库代码是逐行对应推导的，90% 的"代码 bug"其实是接线、符号和标定问题。

## 附录 B 新手黑话表

| 词 | 大白话 |
|---|---|
| HAL | ST 官方的"驱动函数库"，`HAL_I2C_Mem_Read` 就是"帮我读 I2C 器件的寄存器" |
| 占空比 | PWM 里高电平的时间比例，0.95=几乎全速，0.05=几乎不动 |
| 死区 | 占空比太小时电机"纹丝不动"的那段——必须标出来补偿 |
| 中值 | 车真正能平衡的角度，因装配误差≠0°，要标定 |
| gating | 上电"放手条件"：陀螺安静+车扶正+持续 200ms 才进入闭环 |
| I2C 死锁 | 总线被从机拉死、谁都不说话——固件里有 9 脉冲急救 |
| PPO | 一种主流强化学习算法，本仓库用它训练平衡策略 |
| 域随机化 | 训练时故意随机改质量/摩擦等，让策略"见过世面"才好在实车活下来 |
